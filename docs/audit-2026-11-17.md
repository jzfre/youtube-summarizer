# Deep audit — 2026-11-17

## Verdict and scope

The implementation now has substantially stronger, reproducibly tested application boundaries. It is suitable for further validation as a small, single-instance shared-password service. This audit does **not** establish reliable YouTube availability, live summary quality, deployment capacity, or a successfully built container in this environment.

The first pass mainly hardened obvious code boundaries. This second pass inspected the installed upstream libraries, reproduced adversarial cases through the production HTTP server, exercised Chromium workflows, measured live caption retrieval, and tested the actual OpenAI SDK against a local HTTP server. Existing user changes, including original-language selection, were preserved.

No deployment, real model call, or API spending occurred. No provider credentials were configured. Docker was unavailable; container checks are defined in CI but have not been observed running here.

## Functional map and trust boundaries

- The CLI retrieves existing captions; it does not transcribe audio or download video.
- The browser supports four summary styles and optional transcript inclusion. It now exposes cancellation and sign-out, preserves input after failures, and displays a support reference for processing errors.
- Page navigation is session-gated by middleware. Each processing API independently verifies the signed session before reading its body. This distinction is necessary to avoid middleware body buffering.
- Validated requests launch Python with an argument array, without a shell. One per-process concurrency budget is shared across the three routes. Timeout, disconnect, or excessive output terminates the child; its slot is held until process exit.
- Python parses recognized YouTube hosts/IDs, selects captions, and sends the complete accepted transcript to the configured model. Transcript text is untrusted data, separated from summary instructions.
- CLI success/error JSON is validated and mapped to safe HTTP output. No database, persistent queue, result storage, distributed limiter, or per-user quota exists.

## Remaining release gates and design limits

1. **Live summary quality is unverified.** Configure a supported model/account, run [the live evals](../cli/evals/README.md), review every generated claim against its source, and add representative workload transcripts. Synthetic regex checks can still accept unexpected hallucinations; no prompt-injection resistance claim is established.
2. **The observed connection-specific block cleared after the VPN correction.** Direct and authenticated HTTP caption checks passed on 2026-11-18. Blocking remains a possible upstream/network failure; validate the intended deployment network rather than treating the earlier VPN failure as an unresolved application defect.
3. **Container and deployed HTTPS path are unverified locally.** Docker is absent. CI defines a build/non-root/startup smoke gate. Actual proxy timeouts, Secure cookies, forwarded-IP replacement, and host capacity still require deployment checks.
4. **Single-instance access model.** Shared-password sessions and process-local limits fit a small private service. They are not multi-tenant isolation or distributed cost control. Provider-side budgets remain necessary; replicas multiply concurrency. Logout clears the browser cookie; stateless tokens remain valid until expiry or credential rotation. Rotating either the shared password or signing secret now revokes existing tokens after the processes restart.
5. **Caption-language selection is heuristic.** Raw metadata uses a private upstream method. Manual-only captions without a trustworthy speech signal cannot establish original language; fallback selection can be wrong. The lock and fixtures reduce upgrade risk but do not resolve missing metadata.
6. **Bounds have precise scope.** Summary text over 350,000 characters is rejected, not chunked; smaller text can exceed a particular model's token window. YouTube response bodies are buffered before text validation. Network timeouts are inactivity bounds; the web child deadline is the overall bound. Standalone CLI automation needs an external total deadline. Cancelling cannot refund a model request already submitted.
7. **Capacity evidence is a small fault test.** No sustained load benchmark, production SLO, or memory soak was claimed. The application has no durable queue or resume-after-restart behavior.

These are explicit limits of the tested design, not silently passed gates. See [quality and operations](quality.md) for deployment controls and reproducible evaluation instructions.
